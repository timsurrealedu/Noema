# LifeOS Project Memory

## Product and design

- Personal-first responsive web/PWA; self-hosting power user is the initial audience.
- Core promise: capture anything, then expose understandable, reversible AI interpretation.
- Approved visual direction: calm, dark-first, restrained teal, high hierarchy, low visual noise. Show only page-critical information; disclose detail on demand.
- Avoid corporate analytics, chatbot-first, sci-fi HUD, playful widget, glass, gradient, and metric-tile aesthetics.
- Preserve WCAG 2.2 AA fundamentals, original capture sources, non-color state cues, and mobile structural adaptation.
- `PRODUCT.md` owns product intent; `DESIGN.md` owns visual rules. Update them when those decisions change.

## Implementation decisions

- Next.js App Router, React, TypeScript, plain CSS tokens, Phosphor icons. No component framework or state library until complexity earns one.
- The local backend includes Node SQLite/WAL persistence, FTS5, projects, task dependencies, note backlinks, single-owner scrypt authentication and hashed sessions, idempotent/version-checked core APIs, durable jobs, a schema-bound Codex worker, and a Bubblewrap-isolated compiler. Captures close the full loop: text or file capture, immutable assets, PDF/DOCX extraction, Gemini OCR/transcription, transactional proposal apply, reversible audit, and SSE progress. Frontend core state hydrates from and mirrors to the API when authenticated, while retaining browser-local fallback. Global search opens exact objects, header notifications persist read state, and Automations uses the API for definitions, enablement, manual runs, history, logs, schedules, and metrics. External integrations, production hardening, and deployment remain.
- `BACKEND_ROADMAP.md` and `FRONTEND_ROADMAP.md` own mutable implementation status and next work; keep transient progress out of this memory file.
- `POST_MVP_ROADMAP.md` defines the release-grade acceptance contract for the seven deferred product areas and their final operational gates.
- Dark is the default; light mode uses the same semantic roles. Teal is limited to primary actions, selection, and active processing; amber/red remain semantic.
- Graphify is maintained in `graphify-out/`; current extraction is code-only because semantic document extraction needs an external LLM backend.

## Commands and gotchas

- Install: `npm install`
- Run: `npm run dev` → `http://localhost:3000`
- Production check: `npm run build`
- Browser release gates: `npx playwright install firefox chromium`, then `npm run test:browser`. The suite uses isolated SQLite state and covers Firefox desktop/mobile flows, WCAG 2.2 AA automation, keyboard focus containment, 200% text scaling, four viewport baselines, authentication, capture cancellation/retry, and mobile Chromium installability.
- MVP acceptance is complete: both roadmaps have no open MVP-scoped items; the remaining unchecked frontend items are explicitly deferred beyond MVP.
- Layout scan: `node /home/timsurreal/.agents/skills/impeccable/scripts/detect.mjs --json --scope layout app app/globals.css`
- Graph refresh: `graphify . --update --code-only --no-viz`
- Backup: `npm run backup`; verify independently with `npm run verify:backup -- <file>`.
- Portable export: Settings → Data → Export workspace downloads a `.tar` containing `workspace.json` and original assets; credentials, sessions, provider secrets, push endpoints, rate limits, TOTP replay state, and idempotency records are excluded.
- v1 import: `npm run import:v1 -- <export-directory>`.
- Do not run `npm run build` while `npm run dev` is active: both write `.next` and can corrupt the dev server manifest. Stop dev, build, then restart.
- `npm audit` reports transitive Next.js `postcss`/`sharp` advisories. Its suggested `--force` repair downgrades Next.js to 9.3.3; do not apply blindly.
- Login rate limiting is durable in the `login_attempts` table (5 attempts per 15 minutes per identity, surviving restarts). Authenticator secrets persist per user with AES-256-GCM under `LIFEOS_ENCRYPTION_KEY`; enrollment requires confirmation, recovery codes are shown once and stored as scrypt hashes, use is atomic, disable requires password reauthentication, and security changes are audited. `LIFEOS_TOTP_SECRET` remains a temporary login fallback until persisted enrollment, after which it is disabled for that user. Sensitive API checks require MFA verified within ten minutes. Unsafe authenticated requests enforce same-origin checks. Sessions list via `/api/v1/auth/sessions` and revoke per device. Failed jobs retry up to `max_attempts` (default 3) and expired leases are reclaimed by the next worker claim; cancel requests are honored at claim time. Failed browser mutations persist in IndexedDB with dependency, retry, conflict, and idempotency metadata; Web Locks serialize multi-tab replay, reconnect and Background Sync trigger retries, and server idempotency provides exactly-once effects.
- Settings profile, preferences, notification policy, agent permissions, calendar preferences, and backup policy persist per user in versioned SQLite records through `/api/v1/settings`. The Settings UI uses those records plus live MFA and session APIs. Password changes require the current password, use scrypt, append an audit event, and revoke every other active session.
- Sensitive approvals persist the user, authenticated session, recent MFA timestamp, canonical SHA-256 action hash, risk, expiry, commands, files, and diff. Approval is session-bound, expires within ten minutes, and is atomically single-use. The compiler now presents the exact command, affected file, and source for review, then consumes the matching approval before execution.
- Coding shows persisted approval history and launches the real isolated compiler flow; fabricated agent sessions and the client-only approval button were removed. Editing reviewed source invalidates the pending approval, and the backend rejects any action-hash mismatch.
- Login accepts either a current authenticator code or one single-use recovery code. Settings can regenerate recovery codes after recent MFA verification (atomically invalidating every prior code) and disable MFA after password reauthentication.
- Playwright Firefox coverage exercises the complete authentication browser boundary against an isolated database: enrollment, fresh-window TOTP login, recovery-code login, named-device session revocation, and rejection of the revoked cookie.
- Offline file captures store the original Blob and capture metadata in IndexedDB. Replay uploads the immutable asset first, then creates the dependent capture with a stable idempotency key; content hashing deduplicates repeated uploads, and the Blob is deleted only after both server writes succeed. Pending, failed, retry, and conflict states share the global sync indicator.
- Study loads courses, assignments, due cards, and quizzes from authenticated APIs with explicit loading, empty, and error states. Course creation/archive, assignment status changes, spaced-review ratings, and server-graded quiz attempts persist immediately. Quiz reads omit answer keys, and all Study upload copy reflects the enforced 50 MB limit.
- Projects use explicit relational links to tasks, events, notes, assets, captures, and automations. Project workspaces derive tabs and activity from canonical objects and audit history, with persisted milestones, blockers, status/archive changes, relationship link/unlink APIs, and fixture-free empty/loading/error states.
- Contextual recommendations persist their proposal, source objects, provider, provenance, feedback, and disposition. Project recommendations derive from explicit blockers and milestones. The assistant shows source-backed drafts; rejecting changes only disposition, while accepting routes task creation through the existing audited object API.
- Vault Markdown renders fenced `mermaid` flowcharts and fenced `chart` label/value datasets without external scripts. Diagrams and charts expose accessible SVG labels; charts include equivalent semantic tables, and every structured block preserves its source with invalid Mermaid falling back visibly to code.
- PDF assets support versioned page-coordinate highlights, ink paths, text annotations, comments, and links to notes or courses. Normalized coordinates are validated, mutations are audited and idempotent, annotations export as portable JSON, and `/assets/:id/annotate` provides the source-and-annotation workspace.
- Durable jobs support explicit retry-now with preserved event history, immediate queued cancellation, cancellation checks during AI provider events and before result commits, and guarded terminal transitions. Job SSE emits monotonic IDs, honors `Last-Event-ID` (plus query fallback), sends heartbeats, and closes on terminal state.
- Today quick capture now persists before enqueueing interpretation, renders only returned job objects, applies them through the audited capture transaction, and leaves transient SSE disconnects to native `EventSource` reconnection. Firefox coverage verifies queued cancellation and retry from the Capture UI.
- Notifications fan out to durable per-subscription delivery records. The worker claims deliveries transactionally, signs and encrypts Web Push through VAPID, records provider status/responses, retries with bounded exponential backoff, marks permanent failures, and removes subscriptions on HTTP 404/410. Authenticated APIs expose delivery status, retry, and resolve controls.
- `/notifications` groups and filters persisted notifications, marks all read, exposes per-device delivery state and failure reason, supports retry/resolve, and deep-links to related tasks, events, notes, or projects. Notifications persist optional related-object coordinates rather than embedding navigation guesses in the UI.
- Notification and automation pages consume authenticated snapshot SSE streams with browser-native reconnect delays and heartbeats; every reconnect starts with authoritative database state. Skill automation runs persist their linked durable job, remain queued/running until that job terminates, propagate completion/failure/cancellation, and expose guarded cancel/retry controls. Notification automations still finish synchronously after durable notification creation.
- Automation definitions now have authenticated dry-run previews, strict five-field cron validation, version-checked updates, and version-checked deletion; the visual builder and step execution remain tracked in `POST_MVP_ROADMAP.md`.
- The responsive Automation builder exposes create, edit, duplicate, pause, preview, and delete workflows, chooses managed skills from the authenticated registry, and keeps run controls available on mobile.
- Capture-triggered automations now execute exactly once inside the idempotent capture lifecycle. Validated source/text conditions either run the action or persist an explicit skipped run; skill jobs receive bounded trigger context.
- Automation workflows persist an immutable, ordered snapshot of every notification/skill step per run. Notification steps execute exactly once in sequence; one optional terminal skill step hands off durably to the job worker, with per-step completion, failure, cancellation, output, and retry state.
- The Automation builder composes up to ten source/text conditions and ten ordered notification/skill actions, supports keyboard-accessible reordering/removal, previews the complete flow, adapts to mobile, and exposes immutable step history per run.
- Saved paused automations can be test-run explicitly without enabling their trigger; test runs use the same durable step engine and remain visible in run history.
- The workspace knowledge graph incrementally projects canonical tasks, events, notes, projects, captures, assets, automations, courses, and assignments into persisted typed nodes and provenance-backed edges. Authenticated neighborhood/path APIs cap traversal size and expose labels/identifiers only—never note bodies, capture text, or project summaries.
- Audit inverses are structured operations: `delete` (un-create), `restore` (full prior row), `capture-status`, and `delete-many` (interpretation apply). Undo executes the inverse in a transaction and appends a new non-reversible `undo` audit event; history is never deleted.
- Tasks and events persist absolute reminder timestamps. The worker atomically converts due reminders into notifications and records delivery timestamps, preventing duplicate delivery after restart.
- Calendar events use absolute start/end timestamps with timezone, all-day, recurrence, and soft-deletion metadata. Legacy week-grid `day`/`time` rows migrate deterministically from their creation week while those fields remain as compatibility projections. Search and state omit tombstones; deletion is version-checked and audited.
- Google Calendar OAuth uses expiring, user-bound state; encrypts access/refresh tokens with `LIFEOS_ENCRYPTION_KEY`; refreshes expired access; paginates calendar discovery; persists selected calendars, scopes, health, and redacted errors; and supports provider revocation. Settings exposes connection diagnostics and selection without returning tokens.
- Selected Google calendars support paginated initial import and incremental pulls with durable sync tokens, explicit local/Google mappings, etags, recurrence, all-day events, deletion tombstones, and expired-token recovery. Duplicate deliveries are idempotent. Concurrent local and Google edits preserve both snapshots as one reviewable conflict instead of overwriting either side.
- Local Calendar changes use a durable, versioned Google write outbox. New events can target one selected calendar; mapped updates/deletes carry stable IDs and etags, retry rate-limit/server failures with bounded backoff, and turn precondition failures into reviewable conflicts. Calendar offers keep LifeOS, keep Google, or keep both; resolutions are transactional and audited.
- Google Calendar meets the MVP integration contract. Backend integration tests cover OAuth/revocation, refresh, paginated initial and incremental pulls, deduplication, tombstones, retry, two-way writes, and all conflict resolutions; frontend checks cover connection, selection, diagnostics, destination choice, and review controls.
- Analytics is local and disabled by default. `/api/v1/analytics` accepts only fixed navigation, operation, and sync events whose properties are enum values or non-negative numbers; free text, object IDs, note/capture bodies, attachments, prompts, and extracted text cannot enter the schema. Settings controls opt-in and permanent event deletion.
- Global search defaults to local SQLite FTS/LIKE. Users can explicitly enable semantic ranking, which sends bounded titles/excerpts to the configured OpenAI `text-embedding-3-small` model, labels the provider/model in results, and unions every local hit back into the ranked result. Missing keys, invalid responses, and provider failures return unchanged local results; full note bodies are omitted from the search API response.
- Notes have a persisted Draft state. Draft optimization runs as a durable, read-only AI job, stores the original and proposed Markdown for explicit review, applies transactionally, records AI provenance, and remains recoverable through note versions.
- Tutor sessions and messages persist per note or code subject with citations and provider provenance. Note insertion is explicit, idempotent, transactional, recorded against the source Tutor message, and reversible through note versions and audit history.
- Uploads stream to a temp file, are MIME-whitelisted (PDF, DOCX, text, images, audio) and size-capped (50 MB), SHA-256-hashed, and atomically moved into a sharded object store under `.data/objects/`; identical content deduplicates to one asset row. Originals are served immutable from `/api/v1/assets/:id`, captures link assets through `capture_assets`, and the worker feeds raw text, `pdftotext`, DOCX XML, or Gemini OCR/transcription into interpretation prompts.
- Ten v1 AI workflows are managed in `skills/` and passed explicitly to isolated Codex runs; global user skills remain ignored. Vault and compiler tutors are read-only until the user applies their output.
- AI provider order is Codex → Gemini → OpenAI. `GEMINI_API_KEY`/`GOOGLE_API_KEY` and `OPENAI_API_KEY` stay server-only; failover is limited to disabled Codex or explicit capacity/quota errors. OpenAI uses `chat-latest` for simple tasks/schedules, `gpt-5.6` low for notes/code, and `gpt-5.6` medium for math/research. Handwritten images enter through file capture and Gemini OCR.
